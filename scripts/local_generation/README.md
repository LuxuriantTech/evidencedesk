# Local 8B runtime draft

This opt-in wiring is a local, unqualified pilot. It is not enabled by the regular Compose file or public demo, and it is not a release qualification.

1. Review the model and runtime licenses linked in `manifest.json`.
2. To validate runtime compatibility in CI without the model, explicitly prepare the runtime alone into a **new** directory: `python3 -m scripts.local_generation.verify_runtime_archive --prepare-dir /absolute/path/to/evidencedesk-runtime`. This downloads only the pinned 22,300,188-byte runtime archive, validates its SHA-256, safely extracts the full runtime tree, and materializes validated internal library symlinks as regular files. The server is not launched. An existing cached archive can be checked without a download using `--archive /path/to/llama-runtime.tar.gz`.
3. On a machine with at least 6 GiB free, explicitly prepare the full pilot into a **new** directory: `python3 -m scripts.local_generation.prepare_8b_bundle --output /absolute/path/to/evidencedesk-8b-bundle`. This downloads the pinned model/runtime, verifies exact byte counts and SHA-256 values, and extracts only validated runtime files/directories. Keep `PROVENANCE.md` and the licenses with the bundle. Preparation does not run the server.
4. Set `EVIDENCEDESK_8B_BUNDLE` to that absolute directory, then opt in. PowerShell example: `$env:EVIDENCEDESK_8B_BUNDLE = 'D:\models\evidencedesk-8b-bundle'; docker compose -f compose.yaml -f compose.local-8b.yaml --profile local-8b-pilot up api local-8b`.
5. Stop with `docker compose -f compose.yaml -f compose.local-8b.yaml --profile local-8b-pilot stop local-8b api`.

The sidecar is a CPU-only Ubuntu 24.04 amd64 image with a digest-pinned base. It shares only the API container's network namespace, binds to `127.0.0.1:50193`, publishes no host port, runs as UID/GID 65532 with a read-only root and model bundle, drops capabilities, disables swap, limits memory to 10 GiB and CPU to four cores, and lowers its priority with `nice 10`. API identity is checked lazily for each answer request; startup has no inference-server dependency, so there is no Compose start-up cycle.

Only the 8B pilot is present. The rejected 4B runtime has no preparation or Compose path. No application document, session, or answer is written to the model bundle by these scripts. The bundle contains only pinned model/runtime assets and license/provenance text. The server logs remain normal container logs; do not publish them with private prompts or documents.

The image base digest is the official Ubuntu 24.04 multi-platform index digest, with this build constrained to `linux/amd64`; the CI build must still validate runtime compatibility and dynamic libraries. Before launch, the loader compares every extracted runtime file and directory against the pinned archive and rejects unexpected paths; internal archive symlinks are resolved and materialized as regular files. This hash check is not an attestation and cannot protect against a privileged or malicious host changing files after verification. The draft has not been built or run with Docker here. A successful asset test does not qualify generation quality or production suitability.
